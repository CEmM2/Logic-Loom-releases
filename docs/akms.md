# AKMS integration guide

AKMS stands for **Adaptive Knowledge Management System**. It adds a structured, domain-aware knowledge graph layer on top of the documents and notes generated by the research workflow.

## What AKMS is

In AKMS terms, knowledge is organized into a directed graph with two broad layers:

- a **global/domain layer** for concepts, patterns, derivations, and reusable knowledge
- a **repository/local layer** for confidence, pitfalls, task history, and project-specific context

This makes AKMS less like a pile of notes and more like a reusable research memory system.

## The AKMS pieces relevant to Logic-Loom

Logic-Loom touches two AKMS-adjacent capabilities:

### AKMS core

AKMS core provides the graph model and graph build/load routines that Logic-Loom can inspect in read-only form.

In practical terms, that enables:

- filtered graph views
- ego-graph slices around one node
- cluster/tag/domain slices
- node inspection and jump-back actions into related review flows

### AKMS node generation tooling

The `AKMS_nodes_gen` package provides the batch-selection and node-generation workflow used to turn curated source collections into candidate AKMS nodes.

That includes:

- a **Batch Picker** UI for assigning papers to NotebookLM notebooks
- serial or batch extraction workflows
- validation tooling for generated nodes
- promotion flows for moving verified nodes into the vault

## What Logic-Loom currently exposes

When the supporting AKMS resources are available, Logic-Loom may expose:

- **Batches** — ready-to-run starter batches plus your own batch definitions
- **Picker** — batch selection and notebook-oriented paper grouping
- **Nodes** — generated-node browsing, validation, and review, with a bundled curated library of established nodes
- **Graph** — read-only graph exploration based on AKMS core data
- **Learn** *(in active testing)* — compile AKMS knowledge into learning artifacts

## Curated node library and starter batches

As of **v0.1.0-alpha.5**, the app ships two seeded layers so the AKMS tabs are useful the moment they unlock:

- **Established node library (Tier A)** — a read-only, versioned set of vetted knowledge nodes, unioned into the graph as a second source with provenance and tier stamped on each node. A build guard refuses to bundle anything not marked `status: established`, so the shipped library is authoritative by construction. The UI badges **Established vs Draft/Generated**, offers a **report-an-error** path, and a **copy-to-my-vault** action to fork an established node into your own editable workspace.
- **Starter batches (Tier B)** — a starter-batch seed pack dropped into your AKMS workspace on first run, framed clearly as draft/generated content that is yours to run and edit — never co-mingled with the Tier-A library.

Established content grows through a **draft→established promotion path**: a reviewed draft is validated against the schema, stamped `status: established`, given a provenance sidecar, and filed into the curated tree — with the build guard as the mechanical backstop.

## AKMS Learn

As of **v0.1.0-alpha.3**, Logic-Loom ships a **Learn** tab backed by the vendored
`akms-learn` engine. From **alpha.4** on, the modes that need an LLM are driven by
the single unified provider setting (see the [overview](logic-loom.md)). Given a slice of the AKMS graph and a learning request, it
compiles a **Learning Source Packet (LSP)** — a reproducible artifact with a
reading order, per-node section extraction, pitfalls, assessment items, code
links, and a validation block — and exports it in a chosen format.

A few things worth knowing:

- The UI is **capability-driven**: the available generation modes and exporters
  come from the backend, and any mode that is unavailable or merely planned
  renders disabled rather than failing when you submit.
- A handful of generation modes need an LLM. Those activate only when the host
  supplies an LLM provider; without one, they degrade gracefully to disabled.
- You can hand a graph selection straight to Learn with the **"Send to Learn"**
  action in the Graph view.
- Compiled artifacts are cached locally and never written into the AKMS source
  vault.

Learn is new and still in active testing — treat its modes and exporters as
evolving.

## Important release caveat

AKMS integration is **optional** and release-dependent.

For early public releases, you should assume the following unless the release notes say otherwise:

- AKMS-specific tabs can be gated or unavailable
- a readable AKMS source vault may still be required
- release builds may prioritize core Logic-Loom + zsum flows first, with AKMS features following later

That means the presence of an AKMS tab in the UI is not the same thing as a guarantee that every public alpha ships the full AKMS toolchain.
